# Описание проекта: Сервис бронирования (Booking System)

## 1. Концепция и цель проекта
Данный проект представляет собой классическое многостраничное веб-приложение (MPA) для бронирования ресурсов (например, переговорных комнат, оборудования или записи к специалистам). Приложение сочетает в себе надежность классического серверного рендеринга и высокую интерактивность на клиенте благодаря интеграции современных JavaScript-фреймворков.

## 2. Технологический стек
Проект использует монолитную архитектуру, где бэкенд и фронтенд тесно интегрированы:
*   **Бэкенд и маршрутизация:** Ruby on Rails (классический MVC-подход, рендеринг HTML-страниц через ERB/Slim).
*   **Фронтенд (Интерактивные компоненты):** JavaScript, Vue.js (используется точечно для виджетов, требующих высокой реактивности, без использования Vue Router).
*   **База данных:** PostgreSQL.

## 3. Основной функционал

### Клиентская часть (Вьюхи Rails + Vue.js)
*   **Навигация:** Стандартные переходы по страницам, управляемые маршрутизатором Ruby on Rails.
*   **Интерактивный UI (Vue.js):** Встраивание компонентов Vue в шаблоны Rails (например, сложный виджет календаря для выбора дат и времени, динамические формы расчета стоимости).
*   **Визуализация доступности:** Наглядное отображение статусов объектов с моментальным обновлением (через AJAX/Fetch запросы к серверу из компонентов Vue).
*   **Личный кабинет:** Страницы пользователя для управления своими бронированиями, отрендеренные на стороне сервера.

### Серверная часть (Бэкенд на Ruby on Rails)
*   **Генерация страниц:** Формирование HTML-страниц на сервере и отдача их клиенту.
*   **API для виджетов:** Создание легковесных внутренних JSON-эндпоинтов специально для обеспечения данными компонентов Vue.js.
*   **Бизнес-логика бронирования:** Строгая проверка доступности выбранного ресурса на указанный период времени, защита от двойного бронирования (овербукинга) на уровне транзакций базы данных.
*   **Авторизация и безопасность:** Классическая сессионная аутентификация (например, с использованием гема Devise), разграничение прав доступа.
*   **Фоновые задачи:** Отправка email-уведомлений (ActionMailer) о подтверждении или отмене брони.

### База данных (PostgreSQL)
*   **Схема данных:** 
    *   `Users` (Пользователи)
    *   `Resources` (Ресурсы для бронирования)
    *   `Bookings` (Бронирования, содержащие ссылки на пользователя, ресурс, время начала и окончания).
*   **Продвинутые функции:** Использование типа данных "диапазоны" (Range Types, например `tsrange`) в связке с индексами (GiST) и ограничениями исключения (Exclusion Constraints) для максимально быстрой и надежной проверки пересечений времени на уровне самой БД.

## 4. Архитектура взаимодействия
1.  Пользователь переходит по URL, и **Ruby on Rails** получает запрос.
2.  Контроллер Rails обращается к моделям (и базе данных **PostgreSQL**) для получения необходимых данных.
3.  Rails генерирует HTML-страницу (View) и отправляет её в браузер пользователя.
4.  На загруженной странице инициализируются отдельные компоненты **Vue.js** (например, виджет бронирования).
5.  При взаимодействии с виджетом (выбор даты), Vue.js отправляет фоновые асинхронные запросы к специальным эндпоинтам Rails для проверки доступности без перезагрузки всей страницы.
6.  При итоговой отправке формы бронирования может использоваться как стандартный POST-запрос Rails с перезагрузкой страницы, так и асинхронная отправка через Vue.js.
